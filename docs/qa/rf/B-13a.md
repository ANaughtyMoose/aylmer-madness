## What changed

The cause is the one A-11 found (docs/visual-wave/reports/PERF-CREEP.md). While the AudioContext is suspended, `currentTime` stays frozen at 0. Chrome only prunes an AudioParam event once the clock has passed it, so about 40 per-frame `setTargetAtTime` calls kept growing their event lists, and each new call cost more than the last.

- **No automation while the clock is stopped (audio.js).** These calls now return early while `!this.running`: `engine()`, `skid()`, `wind()` (its `meters` are still updated first, for feel_a06), `whoosh()`, `environment()`, the siren update, `setCabin()`, `setVolume()` and `setPaused()`. The one-shots refuse to build nodes while the clock is stopped, because a node with a stop time in the future would never end: `blip`, `crash`, `honk`, `land`, `misfire`, `heille`, `thud`, `wrench`, and horn-on. Horn-off and siren-off still stop their oscillators, just without a fade.
- **Pending automation is cancelled on every state change.** `_stateChanged()` calls `_sweep()`, which runs `cancelScheduledValues(currentTime)` on every long-lived param, grouped as core, engine, ambience, wind, air and siren. On a return to 'running' it calls `_applyMix()` once, which writes back master (taking pause into account), the engine, effects, radio and ambience buses, and the cabin filter. The per-frame params come back on the next frame.
- **Ambience (ambience.js).** It gets its own `running` getter, and `update()` returns `false` without scheduling anything while the clock is stopped.
- **Automation counter.** `start()` wraps the live context's node factories (`createGain`, `createBiquadFilter`, `createOscillator`, `createBufferSource`, `createDynamicsCompressor`, and the rest), so every AudioParam made on the live context is tapped. `audio.automation()` returns:
  - `{ state, running, scheduled, whileStopped, pending, foreign, refused, sweeps, suspends, tracked }`
  - `pending`: automation queued on this file's own params while stopped that no sweep has cancelled yet.
  - `foreign`: calls made from other files while stopped.
  - `refused`: per-frame calls this file skipped.
- **Safety net for other files.** If code outside audio.js automates a tapped param while the clock is stopped (radio.js `update()` and weather.js `_sound()` both do, every frame), the tap first cancels whatever that param has queued at or after the call's own time. That param then holds one event instead of a growing list. A schedule in time order, such as an envelope, is left intact.
- The offline audition path (`buildEngineVoice`, `EngineDriver`, `RoadDriver` on an OfflineAudioContext) is untouched, because the guards live only in the `Audio` class.

## Per-frame cost against the cap

The cap is "B-13a must reduce".
- **Suspended clock (headless, before the first gesture, or a background tab):** p50 frame interval 6.7 to 9.0 ms and rising before the fix; 2.5 to 2.8 ms and flat after. GPU plus CPU p50 is 4.17 ms in window 1 and 4.15 ms in window 30.
- **Running clock:** the only added work is the tap wrapper, an extra JS call per automation call. Measured in Node at 1.4 µs per frame for 60 calls, which is about 0.001 ms per frame. Net reduction.
- All of these numbers are loaded and indicative. The quiet-window perf8 run belongs to B-12a.

## CONTRACT NOTES (integration owner B-12a; also B-13b and the radio and weather owners)

1. **No main.js or hud.js wiring is required.** The fix is self-contained in audio.js. `window.AYLMER.audio` is already exposed (main.js:3546), so `window.AYLMER.audio.automation()` is reachable as-is.
2. **Telemetry hook (optional).**
   - `audio.automation()` returns `{ state, running, scheduled, whileStopped, pending, foreign, refused, sweeps, suspends, tracked }`.
   - Owned creep is `whileStopped - foreign`, and it must stay 0.
   - `pending` must be 0 after any state change.
   - Suggested place: the B-02 audio log in `tools/review/page-agent.js`, owned by B-13b in B1, as one more column; and/or `snapshotScript` in `tools/qa/lib/perf-instrument.mjs`, so soak windows record it directly. This run used a read-only CDP sidecar instead.
3. **Other per-frame callers should check `audio.running` themselves.** `audio.running` (getter, src/core/audio.js) is the guard to call. Add `if (!this.audio.running) return;` at the top of:
   - `Radio.update()` (src/game/radio.js:1120)
   - `Weather._sound()` (src/game/weather.js:530)
   - main.js:1301, the radio fade-in in `openingDone`. While stopped, `_applyMix` on resume replaces the fade.
   Until then they are coalesced (bounded), not refused.

- **The soak tool's `acceptancePass` is false.** The cause is its pose workload check, not timing. Before window 0 the truck went from z 139.45 (the start snapshot) to z 126.7, then stood still from window 2 to the end. This is intermittent and unrelated to audio:
  - On the fix branch, one 2 min control stayed put and the other started already moved but did not move again.
  - The integration-head control stayed put.
  - The fault is in the prepare/pose or traffic path (tools/qa/lib, game physics), which is outside B-13a's files.
  - The drift criterion itself passed at -13.8%.
  - The run was also not in a quiet window: other agents' browsers were alive, load average 8 to 16.
  - Rule "soaks run once per task", so it was not rerun. The lead's quiet-window soak, or F-11's, should repeat it.
- **AudioHandlers still grew in the soak, 58 to 263 over 30 min.** Every owned one-shot is refused while stopped (smoke: 0 nodes built), so these nodes come from other files that build nodes on the live context: radio.js, weather.js, toothhud.js, intro/score.js. Frame time stayed flat. The fix belongs to those owners: build no node with a future stop time while `!audio.running`.
