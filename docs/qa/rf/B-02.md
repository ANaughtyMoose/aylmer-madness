# B-02 Harness vehicle truth, script beats, audio log, Ranger rerun

Branch rf/b-02, from fix/look-on-qr at ac088d1. Tooling only: nothing under src/ changed, so the game's per-frame cost is 0 ms (cap: none listed for B-02; the wave B allotment is untouched). The audio log and the vehicle tracker run inside the harness's injected page agent only (a few wrapped audio calls and one 1 s timer), never in a player's game.

## What changed

- `tools/review/harness.mjs`
  - Vehicle truth. Every beat asserts its start vehicle: the beat's `vehicle` (an id, or `false` for no check), else the plan's `vehicle`, else `ranger`. Missions and courses check each column after the seed; speedRun, crash, jumps, cops, freeRoam, tour, radio, modes and script beats check before they run; boots are never checked. A miss prints `harness: wrong vehicle`, the beat still plays (evidence kept), the result carries `vehicle: { want, got, ok }` and `harness`, SUMMARY.md gets a "Vehicle truth" FAIL line and vehicle columns in the missions table, `headline.wrongVehicleBeats`, `headline.wrongVehicleFresh` and `headline.wrongVehicle` go in metrics.json, and the run exits 1 (`--vehicle-observe` records without failing).
  - The fresh column is a fresh Ranger. `carState()` now holds the vehicle and every parked car; `setCar({ vehicle })` swaps into the asked vehicle where the truck stands through the game's own `G.swapCar`. A job that started in the wrong vehicle is always rerun fresh; afterwards the played vehicle and parked cars go back, so the next beat still carries what the played run left (this is why the bug shows on every later beat). `jumps` uses a fresh Ranger per ramp and restores at the end.
  - Script beats: `{ "do": "script", "id": "<name>" }` imports `tools/review/beats/<name>.mjs` and calls `run(page, assert)`. Later tasks add beats as new files without editing harness.mjs. Template: `tools/review/beats/sample.mjs`.
  - Audio log: per beat, under `### audio <beat>` in transcript.txt, plus `audio.csv` for the whole pack.
- `tools/review/page-agent.js`: `bot.vehicle` (every vehicle the bot drove in the task, in order, for example `ranger>dbike>cart`) and `bot.vehicleSecs`; `state().vehicle`; `RV.vehicle()`; the audio log (one row a second: vehicle, km/h, mean engine rpm main.js asked for, firing pitch Hz, mean load, AudioContext state, cab, siren, radio off/blocked/station name with music or talk, the cues fired that second). The radio is named by station only, never a track, title or file.
- `tools/review/gaps.mjs` (new): the longest gap between on-screen events per job and the gaps over `--over` s. Any overlay text is an event except the street label and the date line (`--all` keeps them); audio rows never count. Writes `<pack>/GAPS.md`.
- `tools/review/compare.mjs`: a vehicle table after the outcome table (per job, both columns, the WRONG flag; non-job beats listed with their start vehicle). Packs from before B-02 say "no vehicle recorded". The CLI is guarded so `vehicleTable` can be imported.
- `tools/review/plans/ranger-rerun.json` (new): Balade libre reload, golfcart, arcsurchauffe to blitz (both races, arcdernier still hand-play), speedRun, jumps, both crashes, cops at 2 and 4 stars, both courses, freeRoam; `vehicle: "ranger"`.
- `tools/review/plans/quick.json`: ends with the sample script beat.
- `tools/review/README.md`: vehicle truth, script beats, audio log, dead air, ranger-rerun, `--vehicle-observe`.
- `tools/smoke_review_vehicle.mjs` (new): gaps parse and filters, vehicle table, beat files export `run`, ranger-rerun and quick plan contents.

## CONTRACT NOTES (integration owner)

- No main.js or hud.js wiring is needed. The harness reads the vehicle from `G.veh.spec.id` (falling back to `G.carId`) and swaps with `G.swapCar(id)` after writing `G.parked[id]`; keep `G.swapCar` and `G.parked` as they are, or tell B-02's owner if they change.
- The audio log wraps these `window.AYLMER.audio` instance methods: `engine(rpm, load, ...)`, `horn`, `siren`, `skid`, `whoosh`, `blip`, `chime`, `crash`, `honk`, `land`, `misfire`, `heille`, `thud`, `wrench`, and reads `audio.ep.cyl`, `audio.ctx.state`, `audio.inCab` and `AYLMER.radio.state()` (`on`, `wantOn`, `stationName`, `onBreak`). A new sound should go through one of these methods (or be added to the list in page-agent.js) to show in the log.
- Wave gate: `node tools/review/harness.mjs --plan ranger-rerun --columns both` exits 1 on any wrong-vehicle beat. `node tools/review/gaps.mjs --pack=<new> --over 45` gives the C gate's dead-air number. New harness beats go in as `tools/review/beats/<id>.mjs` plus a `{ "do": "script", "id": "<id>" }` plan entry.
