## Unmet, and why: Tom's step

The delete guard refuses the index-only untrack, and that is right here. Once a commit dropping docs/STORY-LEDGER.md from the index is merged, git **removes the file from the disk** of every worktree that takes the merge, including wt-qr-look, where the scan and the story tools read it. So Tom runs the untrack himself, in this order:

1. Copy the ledger to the private folder first:
   `cp "/Users/thomaslever/Desktop/Coding Projects/wt-qr-look/docs/STORY-LEDGER.md" "/Users/thomaslever/Desktop/Coding Projects/aylmer-madness/references/STORY-LEDGER.backup.md"`
2. In wt-qr-look, take the ledger and the tracked references file out of the index (both stay on disk there):
   `git -C "/Users/thomaslever/Desktop/Coding Projects/wt-qr-look" rm --cached docs/STORY-LEDGER.md` and
   `git -C "/Users/thomaslever/Desktop/Coding Projects/wt-qr-look" rm -r --cached references`
3. Commit in wt-qr-look. Every other worktree that later merges or rebases onto it loses its copy of those files from disk. Copy them back from the backup if a tool needs them. privacy-scan already falls back to wt-qr-look's ledger.

After that, smoke_privacy's note becomes a passing check, and `--worktrees` passes for each worktree once it takes the commit.
