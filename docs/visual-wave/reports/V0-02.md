# V0-02 World seams: report

Branch `vw/V0-02` from `fix/look-on-qr` 0f5f8ac. No visual change, by design: this task only moves code.

## What changed

`src/game/world.js` went from 3,110 lines to an orchestrator of about 165 lines. It keeps every public export (`buildWorld`, `nightAmount`, `buildHeadlights`, `HOUSE_NEAR`, `MARINA_QUAYS`, `MARINA_BOX`, `clipRoads`, `baseHeightAt`) and the returned world object has the same keys in the same order.

Every section of the old `buildWorld` is now a function over one shared build context in `src/game/world/`. world.js calls them in the order the single function ran them, so every `mulberry32` stream draws in the same order.

**What later tasks read from `ctx`** instead of re-deriving it:

- `ctx.trees`: `{x, z, y, height, crown, kind, conifer, scale}` for every tree baked. Height and crown are the classic mesh's sizes; the prototype leaf-card trees are about the same.
- `ctx.poles`: every upright post (signals, stop signs, lamps, hydro poles, small trees).
- `ctx.houses`: `{bi, id, p, c, y, lo, yaw, lot: {front, archetype, attrs}}` for every archetype house, and `ctx.buildings` for every footprint.
- `ctx.roadSegArr` / `ctx.roadGrid`: the road segments, 7 slots each (ax, az, bx, bz, rad2, hw, road index), and `ctx.roads`.

**Bake hook.** `ctx.postBuild(fn)` queues `fn(ctx)`. world.js runs the queue once every builder is filled (after section 9) and before the upload. An emitter can register its bake from its own file.

**How the move was made.** The section bodies were cut out of the original file by line range, unchanged, and each module's imports and `const {...} = ctx` lines were generated from a scope analysis (eslint-scope), which also checked that nothing reads a name before the section that makes it has run. The cross-section counters moved to `ctx.count`. Three late bindings became explicit: `addWallSegment` reads `ctx.pavedAt`, `snapPole` reads `ctx.free`, and the stamp-array growth after section 7 is `ctx.growSegQuery()`. Em dashes in moved comments became " - "; the one in the console log string is runtime output and was left as it was.

## Verification

All on the same machine, under heavy load from other agents (load average about 58).

1. **Geometry, byte for byte.** A stub renderer hashed every uploaded buffer in upload order (vertex, index, uv and rect arrays, bounds), plus the world's stats, poles, signal plans, furniture log, the return-object shape and 441 probe queries (`groundAt`, `waterAt`, `roadAt`, `nearestRoad`, `querySegments`). Before (0f5f8ac) and after are identical for: the whole town with the stub materials; the whole town with materials passed; each of the four sector slices (aylmer, hull, chelsea, ottawa) as sectors.js builds them; and the prototype path (`isPrototype`, `prototypeStyle`) for the whole town and the aylmer slice. The refactor was also run once with `ctx` wrapped in a proxy that throws on any missing name: no throw, same hashes.
2. **smoke_world.** `node tools/smoke_world.mjs` prints `8097 meshes, 9958434 verts, 5993845 tris`, 1044k near + 230k far house tris, 342 MB vertex data, before and after. The output is identical apart from build milliseconds. 23/23 checks pass. Budgets unchanged.
3. **Pixels.** 42 shots (the 8 core places and the 6 chase poses, each at `day`, `dusk` and `night`, clear weather), `index.html`, SwiftShader, 1088x680 drawing buffer, clock and rAF loop frozen, `Math.random` seeded. Before (pristine 0f5f8ac tree) against after: **all 42 byte-identical, max channel diff 0**. A first pass with the animated actors drawn had 32 of 42 identical and the other 10 differing only where the friend avatars stand (299 Fraser, 129 Frank-Robinson, 75 Denise-Friend): their wave and stride carry boot-timing history, not the bake. The final pass hides the avatars, walkers and debris (props, parked cars and the player stay) and is identical everywhere. 0 page errors in all four runs.
4. **npm test.** Run on the refactor: 74/76 suites, with two wall-clock budgets failing under the machine's load (`smoke_terrain` 2 timing checks, `smoke_react` P8 "streetprops bake < 60 ms": 145 ms). Neither times world.js code. The pristine tree fails the same way under the same load (its full run: 75/76, `smoke_terrain`; its P8 alone: 67 ms). Rerun alone on the refactor: `smoke_terrain` 75/75, `smoke_react` 48/48 three times (52, 45, 39 ms). A second full run on the refactor: 75/76, only `smoke_terrain` (the `groundAt` 200 ns timing budget; terrain.js is unchanged), which passes 75/75 alone. Every non-timing check passes.
5. **Boot.** `tools/headless.mjs` on port 8192 / CDP 9492: `index.html` and `prototype.html` both reach drive mode with 0 console errors and 0 exceptions. (The first `index.html` try clicked before the game module had loaded under load and the tool's own step threw; the retry was clean.)
