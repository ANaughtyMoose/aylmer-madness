# V0-01 Shader modules and renderer seams: report

Branch `vw/V0-01` from `fix/look-on-qr` 0f5f8ac. Written 7 Oct 2026 by Claude.

## What changed

- `src/core/gl.js` no longer holds any GLSL. It compiles exactly one program from `shaders/index.js` `assemble()` at start-up and owns the GL state.
- `src/core/shaders/` holds 17 chunks plus `index.js`: `common`, `light`, `tonemap`, `fog`, `sky`, `water`, `material`, `glass`, `car`, `decal`, `wire`, `corona`, `dynlights`, `wet`, `post`, `digicam`, `shadow`. Each exports `UNIFORMS`, `VERT` (vertex-stage GLSL) and `GLSL` (fragment-stage GLSL).
  - `index.js` declares every chunk uniform in both stages, from the tables, and holds the two `main()` functions. They call a fixed set of hooks, so a later task edits its own chunk only:
    - vertex: `waterVertex`, `decalVertex`, `wireVertex`, `spriteVertex`;
    - fragment: `sunLambert`, `sunShadow`, `ambientLight`, `materialTexel`, `materialAlbedo`, `wetAlbedo`, `waterAlbedo`, `dynLight`, `glassShade`, `carShade`, `applyFog`, `tonemap`, `decalShade`, `wireShade`, `spriteShade`, `postColor`, `digicam`, `skyColor`.
  - Every hook starts as the identity, or as the exact old code (sky, water, fog, light, material), so the picture does not change.
  - A uniform declared by two chunks is an error at assembly: one owner per uniform.
- **Uniform registry.** `r.uniform(name, value)` sets any chunk uniform: float, int, vec2 to vec4, mat3, mat4, sampler2D and arrays such as `'vec4[6]'`. A `value` in a chunk's table is set once at start-up. An unknown name throws while developing (localhost, `file:`, `?dev`, Node) and warns once in a deployed build. Writing a `managed` uniform (one the renderer sets itself) resets the per-draw caches.
- **Material routing.** `opts.material` (`world`, `sky`, `water`, `car`, `decal`, `wire`, `sprite`, `particle`) is sent as `uniform highp int uMaterial`. The codes live in `shaders/common.js` `MATERIALS` and are GLSL `#define`s.
  - `opts.water` and `opts.sky` still work. An explicit `opts.material` wins.
  - The old `uSkyMode` and `uWater` floats are gone.
  - `'building'` and `'object'` are aliases of `world`. world.js and landmarks.js already pass `material: 'building'`, for the prototype renderer's shader role.
- **Second sampler.** `uTex2` is on unit 1, bound from `opts.tex2`, and defaults to a 1x1 white texel. A tiled face samples it when its rect u0 is 2.0 or more (the same rect, offset by 2). Nothing emits that yet. Unit 0 is always the active unit again after a draw, because `texture()` uploads through it.
- **Dynamic meshes.** `r.uploadDynamic(maxVerts, { maxIndices, uv, rect })` allocates the GPU buffers and the CPU staging arrays once. `r.updateDynamic(mesh, builder)` copies a MeshBuilder in and sends only the used range with `bufferSubData`, with no allocation. Over capacity throws. `r.free()` gives a dynamic mesh back, and `gpuBytes` counts it.
- **GPU timer.** `r.gpuMs` is the last finished frame's GPU time, from `EXT_disjoint_timer_query_webgl2`. One query runs from `begin()` to `end()`, from a fixed ring of 4. A disjoint frame is dropped. `gpuMs` is `null` without the extension or before a result comes back. `end()` now always runs (it used to return early when nothing was transparent), so the query always closes.
- `gradeLight()` moved to `shaders/light.js`, byte-for-byte (checked with `diff`). `gl.js` re-exports it with `MATERIALS`.
- New `tools/smoke_shaders.mjs` (122 checks) runs under `npm test`. It covers the assembly, the hooks, the registry, routing, the sampler units, dynamic meshes and the timer, using a fake WebGL2 context. It also counts every typed array made during 1,000 frames of `updateDynamic`: there are none.

Files outside the task's `files` list that the acceptance criteria require: `tools/smoke_shaders.mjs` (named in the criteria) and this report. `tasks.json` status is left to the lead.

## Verification

### Identity proof (pixels)

**Result: pass. 45 of 45 shots are byte-identical (max channel difference 0/255; the bar was 1/255).**

- Sets:
  - `core`: the 8 eye poses from PLAN section 4, with poses from `core-refs.json`. Galeries and the marina have no recorded heading, so they use fixed headings of 90 and 200 degrees.
  - `chase`: the 6 game-camera poses (chase cam behind the Ranger; hood cam on the Champlain Bridge approach).
  - `water_marina`: an extra pose above the marina box, so that water draws (swell and ripples) are in frame. The marina core pose turned out to show no water.
  - Environments: each set at noon, golden and night. Until V0-03 adds `AYLMER.time`, these are the game's `day`, `dusk` and `night` phases.
- Method: one headless Chrome session (SwiftShader, 1088x680 drawing buffer) boots the game from this branch, with time frozen and `Math.random` seeded.
  - For each shot, one frame is rendered while every renderer call (`setEnvironment`, `begin`, `draw`, `end`) is recorded.
  - The recorded list is then replayed through the new renderer and through the old `gl.js` (0f5f8ac, loaded into the same page on the same GL context), twice each.
  - Every replay was stable, and old equals new on every shot. Triangle and draw counts match on every shot.
- Why not separate before and after sessions: two boots of the same baseline tree differed by up to 239/255, on up to 97 % of pixels (pedestrians, haze, sky). That evidence is kept in `noise-floor/`.
- Evidence: `references/places/_feedback/visual-wave/V0-01/` in the main checkout, holding `before/`, `after/`, `pixel-diff.txt`, `pixel-diff.json`, `capture.log`, `noise-floor/` and the scripts in `tools/`.

## Notes for later tasks

- Hook signatures are in `shaders/index.js`, in `FRAG_MAIN` and `VERT_MAIN`. Varyings (`vNor`, `vCol`, `vDist`, `vUV`, `vRel`, `vRect`) and `worldPos()` are visible to every chunk.
- Before V0-04 lands, captures from separate sessions are not comparable pixel for pixel: pedestrians, the haze and the sky state differ from one boot to the next. Two baseline runs of the same tree differed by up to 239/255, on up to 97 % of pixels. The proof here therefore renders both renderers in one session, from one recorded frame. V0-04's capture tool should pin the sim state the same way, or record and replay the draw list.
- `smoke_react` has a wall-clock budget (`streetprops bake < 60 ms`) that fails under heavy machine load. It uses a stub renderer, not `gl.js`. It passes on a quieter run.
